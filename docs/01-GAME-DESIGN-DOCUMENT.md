**Status:** Current — describes the shipped v1.0 game as implemented in code. Supersedes the earlier v0.1 "documentation phase" draft of this document.
**Companion docs:** `02-MECHANICS-SPECIFICATION.md` (authoritative ruleset), `03-TECHNICAL-SPECIFICATION.md` (engineering stack), `04-ARCHITECTURE.md` (how the design maps to code), `05-ASSET-PIPELINE.md`, `06-DATA-AND-SAVE-SYSTEM.md`.

## 1. Vision Statement

**Space Arenas** is a browser-based real-time strategy game in the classic *Command & Conquer: Generals* mould: build a base, harvest supplies, manage a power budget, research upgrades, field a combined-arms army, and destroy the enemy. It runs entirely in the browser on desktop, plays solo against AI bots, on a LAN, or over the public online service, and is built from the ground up for **deterministic lockstep multiplayer**.

The game is intentionally a **single-faction, complete implementation** of the Generals formula: one playable faction ("Space Legion") with a full build tree, ground/air/naval units, defenses, stealth, mines, transports, and rank-gated super weapons. The architecture is designed so that additional factions, content, and modes can be layered on without disturbing the deterministic core.

Development-phase graphics are **generated colored shapes and pre-rendered placeholder sprites** with **procedurally synthesized sound effects**; the gameplay, netcode, and architecture are the finished product, and the render/audio layers are drop-in replaceable.

---

## 2. High-Level Game Description

- **Genre:** Real-Time Strategy (RTS).
- **Perspective:** Isometric camera — fixed-angle 2:1 projection, free pan and zoom.
- **Players:** 1 (skirmish vs bots) to 8 (LAN or online), in free-for-all or team alliances.
- **Match structure:** Command Center → Power → Supply → production → tech → army → destroy the enemy.
- **Victory:** Depends on the match **win rule** (see §9) — by default, destroy every enemy Command Center and any surviving production capability.
- **Economy:** dual-resource — **Supplies** (cash, harvested from supply fields by Harvesters) and **Power** (generated by Power Plants, consumed by buildings; a deficit shuts production down).
- **Determinism:** all gameplay runs on a 25 Hz integer simulation, hashed every tick, with CRC32 checksum exchange over the network to detect desyncs.

---

## 3. Design Pillars

| Pillar | What it means in the design |
|---|---|
| **Deterministic first** | Every rule resolves identically on every machine from the same seed and command stream. No floating-point in serialized state, no wall-clock in the sim, fixed system order. |
| **Readable at a glance** | Silhouette + team color identifies every entity; build costs and power draws are visible before committing; hits, deaths, and abilities have clear visual and audio feedback. |
| **Generals familiarity** | Build flow, power-down behavior, harvester auto-routing, garrison/transport, super weapons, and general ranks all echo *Generals / Zero Hour*. |
| **Combined arms** | Infantry, vehicles, air, and naval each answer a threat the others cannot; no single unit wins a match. |
| **LAN and browser first** | Host-and-join in seconds, no install, no account required for LAN/offline play. |
| **Layered depth** | Core combat is simple; stealth, detectors, mines, smoke, transports, veterancy, and super weapons add depth for players who want it. |

## 4. Core Gameplay Loop

```
┌───────────────────────────────────────────────────────────────┐
│  BUILD      Command Center → Power Plant → Supply Dock         │
│  HARVEST    Harvester auto-routes supply field ⇄ Supply Dock   │
│  PRODUCE    Barracks / War Factory / Air Force / Dock          │
│  TECH       Tech Center research: radar, satellite, stealth,   │
│             detector, mines, abilities, transports, dome       │
│  FIGHT      Combined-arms armies, defenses, transports,        │
│             mines, smoke, garrison bunkers                     │
│  SCORE      Kills + harvesting + research + expansion → ★ rank │
│  WIN        Destroy enemy Command Centers / forces             │
└──────────────────────────────┬────────────────────────────────┘
                               │
   Early game: economy + scouting      Mid: tech + map control
   Late game: super weapons, ranks, decisive battle
```

### Core loop details

1. **Build:** Start with a Command Center (and one Bulldozer). Place Power Plants to raise the power budget, then Supply Docks and production structures.
2. **Harvest:** Supply Docks auto-queue free Harvesters; each Harvester cycles between the nearest supply field and its dock, banking supplies on each trip. Supply fields can be *captured* with a Scout for a bonus.
3. **Produce:** Barracks (infantry), War Factory (vehicles), Air Force (fighters), and Dock (naval) each build specific units. Queues are limited (`queueLimit`, default 10).
4. **Tech:** The Tech Center and Super Weapon unlock the research tree; research is gated by both building availability and **general rank (★)**.
5. **Fight:** Units auto-acquire targets in range; the player micro-manages with move, attack-move, keep-attack, guard, formations, abilities, and super weapons.
6. **Score & rank:** Killing units, destroying buildings, docking supplies, finishing research, and expanding all award score. Crossing a score floor promotes the team's general rank, unlocking higher-tier research.
7. **Win:** Reduce the enemy to elimination per the active win rule (see §9).

| Segment | Description | Priority |
|---|---|---|
| **Primary** | RTS veterans (Generals, C&C, StarCraft, AoE) who want a free, browser-based, LAN-capable RTS | High |

## 6. Game Modes

| Mode | Players | Notes |
|---|---|---|
| **Skirmish (offline)** | 1–8 | Player vs AI bots, or a fully local sandbox. Bots have three difficulties. Runs with no network. |
| **LAN (host)** | 2–8 | Node host server (`host/`) runs the authoritative tick relay; clients are pure lockstep. Room code + optional passphrase, QR invites, LAN discovery. |
| **Online** | 2–8 | Public Express service (`online/`) with accounts, match browser, rooms, leaderboard, mods, backups. Same lockstep protocol over WSS. |
| **Spectate** | any | Join an in-progress match as a spectator; receives a full command-log sync and rebuilds the world deterministically. |
| **Replay** | 1 | Load a recorded match; the client rebuilds the world from seed + command history, with play/pause, scrub-seek, and speed controls (`0.25× / 0.5× / 1× / 2× / 4×`). |
| **Map Builder** | 1 | Built-in editor: paint terrain, place supply/oil fields and obstructions, place spawns, import/export JSON maps. |

There is no campaign or mission string; the game is a skirmish/multiplayer product. Progression (XP, ranks, daily missions, achievements) is meta, described in §12.

## 7. Faction & Roster ("Space Legion")

One faction exercises every system: economy, production, defense, air, naval, stealth, mines, transports, and super weapons. All balance data lives in `shared/src/balance/` (`buildings.ts`, `units.ts`, `weapons.ts`, `upgrades.ts`) and is moddable (`shared/src/mod.ts`).

| **Power Plant** | 3×3 | 200 | 20 s | 800 | **+50** | Raises the power budget; supports "Max Power" overdrive |

| **Air Force** | 3×3 | 500 | 25 s | 900 | −15 | Fighters |
| **Super Weapon** | 4×4 | 1500 | 45 s | 1500 | −100 | Limit 1; unlocks Space Laser / Airstrike / EMP and their upgrade research |

- **APC / Carrier / Bunker** are transports; only infantry can board.
- **Fighter** is an aircraft: `capacity` 3 is its home hangar count, `maxAmmo` 2, `reloadTicks` 5 s.

## 8. Economy Design

### 8.1 Supplies

- **Income source:** a Supply Dock's Harvester cycles to the nearest supply field, loads (`harvesterLoadTicks`, default 40 t = 1.6 s), and returns to bank `supplyPerTrip` (default 50) credits.
- **Treasury:** integer credits; starts at `startingCredits` (default 800).
- **Supply capture bonus:** a team whose Scout holds a supply field (uninterrupted presence for `supplyFieldClaimTicks`, default 20 s) banks an extra `supplyFieldBonus`% (default 25%) on every trip from that field. Fields are **never exclusive** — enemy Harvesters still take the base amount. A Scout's absence for `supplyFieldHoldTicks` (default 10 s) drops the bonus.
- **Oil fields (secondary):** a Scout that holds an oil field for `oilClaimTicks` (default 20 s) captures it; the owner then banks `oilIncome` (default 50) every `oilIncomeIntervalTicks` (default 10 s). Oil fields can also be destroyed by combat (`oilFieldHp`, default 500).
- **Crypto mining (naval):** a completed **Crypto Miner** banks `cryptoMinerIncome` (default 500) every `cryptoMinerIncomeIntervalTicks` (default 30 s). It runs only while the team has a completed Dock, at least 3 living Missile Boats and at least 1 living Carrier, and its net power is non-negative (`powerDown` false). The income timer resets to 0 whenever those conditions fail, so no income banks up. Crypto Miners are water-only, 3×3, and must be at least `cryptoMinerSpacing` (default 5) empty tiles from any other Crypto Miner, measured edge-to-edge. Only an empty Carrier (no transported units) can place one.

### 8.2 Power

- **Budget:** `available = Σ powerGen − Σ powerUse` across a team's completed buildings.
- **Power down:** when the net is negative, production queues pause and weaponized buildings stop firing; already-built units operate normally.
- **Max Power:** an operator may overdrive a Power Plant to double its output for `maxPowerTicks` (default 30 s), at the cost of damaging the plant down to 50% of its maximum HP.

### 8.3 Refunds

- Selling a building refunds `sellRefundFraction` (default 50%) of its cost, animated over `sellTicks` (default 3 s).
- A Bulldozer can collect a destroyed building's wreck for `wreckValueFraction` (default 10%) of its cost.

## 9. Combat & Win Conditions Design

- **Damage model:** instant-hit weapons apply damage on the tick their cooldown expires; splash weapons damage all valid targets within the splash radius. No projectile physics simulation (tracers are visual only).
- **Targeting:** units and armed buildings auto-acquire targets deterministically — nearest by scoring with biases for the last attacker, focused fire, and low HP; air targets require a weapon with `targetsAir`.
- **Veterancy:** every 3 kills up to 15 promotes a unit through ranks 1–5, granting +25% damage, +10% range, and +20% armor reduction per rank (armor capped at a 50% damage floor). Rank never regresses. See mechanics spec §7.
- **Garrison:** a Bunker holds 5 infantry; each passenger contributes one volley per cooldown. An empty bunker does not fire.
- **Crush:** vehicles deal `crushDamage` (default 20) to enemy infantry they run over.
- **Mines:** Engineers place proximity mines that arm after 1.5 s and deal `mineDamage` (60) in a small blast; a team is limited to 30 live mines by default.
- **Smoke:** smoke clouds give shots fired through them a 60% miss chance.

### Win rules

`WIN_RULES = ['standard', 'annihilation', 'command-center']`, default `standard`.

| Win rule | A team is eliminated when… |
|---|---|
| **Standard** | It has no units and no buildings; or its Command Center is gone and it has no Bulldozer and cannot afford a new Command Center from credits + refunds. |
| **Total Annihilation** | It has no units and no buildings (Command Center destruction alone is not fatal). |
| **Command Center** | Its Command Center is destroyed. |

The match ends when at most one alliance remains; the winner is that alliance's lowest-ID surviving team. Elimination is bypassed for single-team games, `winless` sandboxes, and once the game is already over.

## 10. Vision, Stealth & Fog Design

- **Fog modes:** `memory` (default — explored tiles stay dim, live vision is bright), `classic` (seen = bright forever), `hard` (loses vision to black instantly).
- **Vision sources:** unit/building vision radii, satellite reveals (6 s at a time, 30 s cooldown), super weapon strikes (laser/EMP reveal their radius, airstrike reveals radius 6), and a short fade band (`fogFadeDistance`, default 3 tiles) that keeps an enemy briefly visible after leaving vision.
- **Stealth & detectors:** stealth-capable units are hidden unless an enemy detector building is within `detectorRange` (12) of them, or they were recently revealed (`stealthRevealTicks`, 3 s).
- **Satellites:** a researched Satellite ability reveals a target area for 6 s, respecting a 30 s cooldown.
- All fog is derived deterministically from the sim — no fog data crosses the wire.

## 11. Super Weapons Design

A single Super Weapon building (limit 1) arms one of three rank-gated strikes, plus leveled upgrade research.

| Strike | Default role | Level scaling |
|---|---|---|
| **Space Laser** | Sustained beam over a small area for 4 s (40 dmg/tick); armed by Space Laser research; also fires a free opening shot from the Command Center if no Super Weapon exists. | Radius and wind-up improve with level (max level 2). |
| **Airstrike** | 4 kamikaze planes bomb a point in sequence (50 dmg each, radius 3). | Damage ×(1 + 0.5·level); radius ×(1 + 0.15·level). |
| **EMP** | Disables enemy units and buildings in a large radius (8 tiles) for 5 s. | Radius ×(1 + 0.15·level); duration ×(1 + 0.5·level). |

All three share a 60 s cooldown (`EMP`/`Airstrike`/`Laser` cooldowns). Choosing a second strike at the Super Weapon (`sw-choose`) requires general rank ≥ 1 and consumes the one-time arm choice; the Space Laser is always armed by default.

## 12. Progression & Meta

Although matches are self-contained, the game tracks persistent progression:

- **Unit veterancy (in-match):** ranks 1–5 at 3/6/9/12/15 kills, as in §9.
- **General rank (in-match, per team):** score floors 500 / 1500 / 3500 award ★1/★2/★3. Score comes from kills (unit 10, building 30), supply trips (2 each), research (15), and expansion placements (25). Ranking up can grant a credits prize (`rankUpPrizeCredits`, default 100).
- **Commander XP / level (profile):** earned from completed matches and daily missions; `DAILY_XP_PER_LEVEL` = 100.
- **Daily missions:** 4 deterministic missions per day (kinds: win / train / build / destroy / supply) drawn from a seeded generator, with XP rewards.
- **Achievements:** evaluated live during a match and at match end.
- **Mode records:** per-mode win/loss/high-score history (`MODE_RECORDS_VERSION` = 2).
- **Profile:** name, XP, level, stats, history cap 50 entries (`PROFILE_VERSION` = 1), with encrypted cloud backups on the online service.

### Co-op settings

Team alliances can optionally share resources and progression (`coopEconomy`: none | power | supply | both; `coopRank`: none | score | level | both; `coopControl`: none | units | all). Shared units are controllable at `coopControl = units`; buildings only at `all`.

## 13. Maps & Content

- **Procedural map presets** (`shared/src/maps.ts`): Breach (2p), Four Corners (4p), Six Settlers (6p), Grand Arena (8p), Dead Man's Pass (2p), Crossroads of Cinder (4p), Sixfold Ring (6p), Shattered Circlet (8p).
- **Auto-sizing:** 128×128 for ≤4 players, 160×160 for ≤6, 192×192 for 8. Manual maps range 16×16 to 512×512. `generateDefaultMap()` is the 128×128 "The Breach".
- **Terrain types** (`Terrain`): Ground, Cliff, Water, Road, BuildableGround. Water and Cliff are impassable; Ground and BuildableGround are buildable.
- **Map contents:** brightness/color hints, oil fields, supply fields (position, radius, capacity), and obstructions (rock/wreck/tree).
- **Map builder:** in-browser editor for authoring and exporting/importing JSON maps; maps can also be imported by other players at lobby time.
- **Mods:** JSON balance mods overriding building/unit/weapon/upgrade values, validated by hash; a community repository lives on the landing site. Match settings also expose per-category overrides.

## 15. Player Experience (The "Feel")

- **Responsive:** local input is applied at the current sim tick; LAN RTTs are typically sub-5 ms, and online play uses the same deterministic lockstep with a small frame buffer.
- **Legible:** distinct silhouettes, team-colored accents, build-progress bars, damage flashes, tracers, and impact effects.
- **Fair:** the host does not simulate the match — it only relays validated command frames and integrity checksums, so there is no host advantage in gameplay logic.
- **Informative:** the HUD shows credits, power net, score/rank, selection details, build queues, research, and a live game log; a dev overlay exposes per-system profiling and debug render toggles.

---

## 16. Performance & Platforms

- **Target:** desktop browsers with WebGL (PixiJS 8). A 25 Hz integer sim and low-poly shapes keep the floor low.
- **Determinism vs. framerate:** render runs at display refresh; the sim advances in fixed 40 ms steps with a bounded catch-up (max 4 ticks) so a hiccup slows the sim rather than desyncing it.
- **Scale:** the shipped test suite exercises 400+ tests including determinism soaks; maps up to 512×512 with fog and pathfinding budgets.

## 17. Scope Guardrails (What the game is NOT)

| Not in this release | Why |
|---|---|
| Asymmetric factions | One complete faction proves every system; more factions are a future content axis. |
| Real production sprites/audio | Dev-phase placeholders by design; the render/audio layers are replaceable. |
| Campaign / scripted missions | Skirmish/multiplayer product; map builder covers custom scenarios. |
| Gameplay-affecting weather | Rain/snow/thunderstorms and the day/night cycle are **purely cosmetic** render effects (`client/src/render/weather.ts`, `dayNight` setting). |
| Host migration / mid-match rejoin | LAN host migration is out of scope; the online service offers a reconnect grace window at the lobby/relay layer. |
| Rollback netcode | Lockstep with fixed command frames; commands are never applied before their target tick. |

### Planned / not yet implemented

The architecture intentionally leaves room for these, but they are **not** in the current build:
- Additional playable factions with asymmetric rosters.
- Pre-rendered sprite/audio asset packs replacing the placeholder art (see `05-ASSET-PIPELINE.md`).
- Campaign or scripted mission strings.
- In-match host migration.
- Cloud matchmaking beyond the current online rooms/browser.
